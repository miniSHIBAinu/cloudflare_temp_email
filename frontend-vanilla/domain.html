Thêm Domain
của bạn

Kết nối domain riêng vào hệ thống TempMail để tạo địa chỉ email tạm thời với tên miền của bạn. Hệ thống tự động tạo Email Routing rule cho mỗi địa chỉ mới qua POST /api/new_address (xem API docs).

1

Chuyển DNS domain về Cloudflare

Domain của bạn phải dùng Cloudflare làm DNS. Nếu chưa, hãy vào nhà đăng ký domain và đổi nameserver về Cloudflare. Sau đó thêm domain vào tài khoản Cloudflare tại dash.cloudflare.com trên cùng account sevengotek@gmail.com (account ID ac634c95…).

Nếu domain đang dùng cho email thật, hãy dùng subdomain (vd: tmp.yourdomain.com) để tránh ảnh hưởng đến email hiện tại.
2

Bật Email Routing

Vào Cloudflare Dashboard → yourdomain.com → Email → Email Routing, bật Email Routing. MX records sẽ tự động được thêm (route1/2/3.mx.cloudflare.net).

Không cần tạo Catch-all rule — hệ thống sẽ tự tạo per-address rule khi user gọi POST /api/new_address thông qua API. Đây là cơ chế Option A trong codebase, work-around cho việc CF API reject literal * matcher.
3

Cập nhật DOMAINS trong worker/wrangler.toml

Sửa 2 dòng DOMAINS và DEFAULT_DOMAINS trong file worker/wrangler.toml (gitignored, local-only). Thêm domain mới vào array, phân cách bằng dấu phẩy:

DOMAINS = ["miraclelab.online", "yourdomain.com"] DEFAULT_DOMAINS = ["miraclelab.online"] # chỉ domain mặc định user mới thấy trong dropdown
Nếu muốn user tạo address với subdomain bất kỳ (vd: tmp.yourdomain.com), bật ENABLE_CREATE_ADDRESS_SUBDOMAIN_MATCH = true ở wrangler.toml.
4

Deploy + test

Sau khi sửa wrangler.toml, deploy lại worker:

npx wrangler deploy --minify

Test thử bằng cách tạo 1 địa chỉ mới qua API:

curl -X POST https://mail-api.miraclelab.online/api/new_address \ -H "Content-Type: application/json" \ -d '{"name":"smoke","domain":"yourdomain.com"}'

Nếu response 200, kiểm tra trong Cloudflare Dashboard → Email → Routing Rules sẽ thấy 1 literal rule mới được tạo tự động với tag addr-{address_id}-{local_part}.

ℹ️ Lưu ý quan trọng

  • Phải cấu hình CF API key trong Worker secrets (đã setup trong project này, xem CONTEXT.md §13.1-13.3). Worker dùng Global API Key để tạo/xoá Email Routing rule qua CF API.
  • Mỗi CF zone giới hạn ~10,000 routing rules. Đủ cho use case personal temp email.
  • Không cần (và không nên) tạo Catch-all rule với action worker — CF API không chấp nhận literal * matcher. Hệ thống tạo per-address rule thay thế (Option A).
  • Address bị xoá qua DELETE /api/delete_address sẽ tự động xoá Email Routing rule tương ứng (cleanup). Không cần thao tác thủ công.
  • D1 có sẵn 23 addresses từ test trước. Mỗi address tương ứng 1 Email Routing rule. Cleanup định kỳ qua auto_cleanup setting.
