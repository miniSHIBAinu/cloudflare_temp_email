#### 3.2.2 Root cause analysis

**CF Email Routing có 3 loại matcher**: `literal`, `all` (catch-all), `regex` (chỉ document nhưng API reject).

**CF API limitations** (verified qua tests):
- Catch-all `type=all` + action `worker` → API reject "Invalid rule operation" (PUT 409) hoặc wrangler reject "Catch-all rule only supports 'forward' or 'drop' action types"
- Matcher `type=regex` → API reject 422 "must be a supported matcher type"
- Matcher `type=literal` với value `"*@miraclelab.online"` → tạo được, nhưng `*` là literal character, KHÔNG phải wildcard → rule không match email thật nào

**7brain.online zone có rule catch-all+worker** (`tag: 615dfb08...`) — rule tồn tại trong config nhưng **KHÔNG actually deliver** đến worker (đã test thực tế).

**Kết luận**: Cloudflare Email Routing hiện tại **không hỗ trợ wildcard-to-worker routing** một cách thực sự. Đây là giới hạn của CF platform, không phải bug code.

## 4. Các vấn đề khác tìm được (Other findings)

### 4.1 🟡 MEDIUM — Static file fallback masks missing paths

`worker.ts:74-86`:
```typescript
if (c.env.ASSETS && !API_PATHS.some(path => c.req.path.startsWith(path))) {
    const url = new URL(c.req.raw.url);
    if (!url.pathname.includes('.')) {
        url.pathname = ""   // ← SPA fallback: serves index.html for ANY non-API path without extension
    }
    const resp = await c.env.ASSETS.fetch(url);
    ...
}
```

Hậu quả: bất kỳ path nào không có extension và không thuộc API sẽ serve `index.html`. Ví dụ:
- `GET /health_check` → serves index.html (route health_check ở line 319 bị bypass)
- `GET /foo` → serves index.html
- `GET /api/foo` → vẫn OK vì check API_PATHS trước

→ Cần thêm allowlist (vd: chỉ fallback cho `/`, không cho paths khác).

### 4.2 🟡 MEDIUM — Auto-refresh leak khi JWT expired

`app.js:170-178`:
```javascript
if (msg.includes('expired') || msg.includes('401') || msg.includes('credential')) {
    showError('Phiên đã hết hạn, vui lòng tạo email mới');
    setEmail('', '', '', '');   // ← clears state nhưng KHÔNG stop interval
}
```

Hậu quả: setInterval vẫn chạy mỗi 5s sau khi JWT expired, gọi `loadMessages` (line 164: `if (!S.jwt || !S.user) return;` — silently return). Resource leak nhỏ (interval không bao giờ clear), không ảnh hưởng UX nhiều.

### 4.3 🟡 MEDIUM — delete-all-btn N+1 queries

`app.js:297-300`:
```javascript
for (const m of S.messages.slice()) {
    await api('DELETE', '/api/mails/' + m.id, null, true);  // sequential
}
```

Nếu user có 50 emails → 50 sequential round-trips. Worker không expose batch delete endpoint. Có thể cải thiện bằng cách thêm batch endpoint hoặc dùng `Promise.all` (parallel).

### 4.4 🟢 LOW — JSON key `sender` vs `from` mismatch risk

`parsed_mail_api.ts` trả field `sender` (không phải `from`). Frontend mapping qua `normalizeMessage` (line 110-118). Đã xử lý đúng nhưng dễ vỡ nếu worker đổi schema.

### 4.5 🟢 LOW — `S.openRequest` có thể overflow

`app.js:183`: `const requestId = ++S.openRequest;`. Number.MAX_SAFE_INTEGER = 2^53. Không bao giờ xảy ra trong thực tế nhưng về lý thuyết có thể overflow.

### 4.6 🟢 LOW — Iframe sandbox restrict quá mức

`app.js:197`: `iframe.setAttribute('sandbox', '')`. Không có `allow-popups`, `allow-popups-to-escape-sandbox`, etc. Nghĩa là user không thể click link trong email HTML để mở tab mới. Có thể thêm `allow-popups` nếu muốn UX tốt hơn.

### 4.7 ✅ GOOD — CSP + X-CTO + Cache headers

Đầy đủ và đúng chuẩn. Frontend dùng external script `https://static.cloudflareinsights.com/...` được allow trong CSP.

### 4.8 ✅ GOOD — JWT exp validation

`worker.ts:156-159`: Check `payload.exp < Math.floor(Date.now() / 1000)`. Đúng format.

### 4.9 ✅ GOOD — D1 queries dùng prepared statements (no SQL injection risk)

`worker/src/email/index.ts:80-84`: `env.DB.prepare("INSERT INTO ... VALUES (?, ?, ?, ?)").bind(...)`. Đúng pattern.
